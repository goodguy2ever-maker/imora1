# IMORA 2.0

Строительный проект под полным цифровым контролем — от архитектурного чертежа и сметы до готового объекта.

IMORA 2.0 — единая цифровая экосистема для девелоперов, генеральных подрядчиков и архитекторов. Проект разделен на 3 ключевые части (Монорепозиторий):

1. **Часть 1 (`apps/landing`):** Лендинг и брендинг с интерактивной трансформацией (Чертеж 2D → 3D-BIM спецификация → Реализованный комплекс), калькулятор окупаемости, тарифная сетка и сбор заявок.
2. **Часть 2 (`apps/platform`):** Авторизация, роли (SUPER_ADMIN, COMPANY_ADMIN, MEMBER), биллинг, онлайн-оплата и панель управления компаниями.
3. **Часть 3 (`apps/workspace`):** Инженерный воркспейс: 2D-САПР чертежей стен, версионные сметы, согласование заявок на материалы, план-факт расходов и журнал стройки.

## Стек

- **Frontend:** Vite 7, React 18, TypeScript, Tailwind CSS 3, Lucide React
- **Backend:** Supabase (PostgreSQL, Row Level Security, RPC-функции, Edge Functions)
- **Тема:** Технологичная тёмная (dark architecture mode)

## Структура Монорепозитория

```
imora/
  apps/
    landing/       # Часть 1: Промо-лендинг, интерактивный визуализатор трансформации
    platform/      # Часть 2: Доступ, авторизация, биллинг, супер-админка
    workspace/     # Часть 3: 2D-редактор чертежей, сметы, снабжение, финансы
  packages/
    ui/            # Общие UI-компоненты
    shared/        # Общие хелперы и утилиты
  src/             # Ядро клиентского приложения
  public/
    images/        # Архитектурные чертежи и фото готовых объектов
  supabase/
    migrations/    # Миграции базы данных и RLS-политики
    functions/     # Edge-функции управления пользователями
```

## Переменные окружения

Файл `.env` содержит:

- `VITE_SUPABASE_URL` — URL проекта Supabase
- `VITE_SUPABASE_ANON_KEY` — anon-ключ Supabase

Service-role ключ используется только в edge-функции и хранится в секретах Supabase.

## Миграции

1. **buildai_01_core_access** — компании, профили, журнал аудита, заявки на демо. Хелпер-функции `app.my_company_id()`, `app.is_super_admin()`, `get_my_access()`. RLS и гранты.
2. **buildai_02_workspace_tables** — проекты, версии смет, строки смет, задачи, заявки на материалы, расходы, ежедневные отчёты. Составные FK (id, company_id). RLS по компании и роли.
3. **buildai_03_business_functions** — серверные функции: создание компании, версии сметы, утверждение сметы, workflow заявок, дашборд. Аудит действий.

## Создание SUPER_ADMIN

После применения миграций создайте первого платформенного администратора:

1. Создайте пользователя в Supabase Auth (через панель Supabase или SQL).
2. Вставьте профиль:

```sql
INSERT INTO public.profiles (id, role, full_name, email, status)
VALUES ('<uuid-пользователя>', 'SUPER_ADMIN', 'Имя Админа', 'admin@buildai.ru', 'active');
```

3. Войдите через `/login` — вас перенаправит на `/admin`.

## Создание компании

1. Войдите как SUPER_ADMIN.
2. На странице «Компании и доступ» нажмите «Создать компанию».
3. Заполните данные компании и администратора.
4. Администратор компании получит email и пароль для входа.

## Edge-функция manage-users

Обрабатывает: `create_company`, `create_team_member`, `update_team_member`, `reset_team_password`. Использует service-role ключ, проверяет JWT вызывающего. Конфигурация в `supabase/config.toml` (`verify_jwt = true`).

## Изоляция компаний

- Каждая таблица данных имеет `company_id`.
- RLS-политики используют `app.my_company_id()` — возвращает компанию только если профиль активен AND компания открыта (статус trial/active AND access_until > now()).
- Приостановленные и истёкшие компании теряют доступ, но данные сохраняются.
- Составные FK (id, company_id) гарантируют, что строки не могут ссылаться на чужие проекты.
- Роли и компания проверяются на сервере, не в браузере.

## Известные ограничения

- Нет восстановления пароля по email (только сброс админом).
- Нет экспорта данных.
- Нет интеграции с внешними системами.
- Мультиязычность только RU.

## Демо-сценарий (5 минут)

1. **Лендинг (30 сек):** Откройте `/`. Покажите заголовок, проблемы, возможности, форму заявки на демо. Нажмите «Войти».

2. **Вход как SUPER_ADMIN (30 сек):** Войдите как платформенный администратор. Вы попадёте на `/admin`.

3. **Создание компании (1 мин):** На «Компании и доступ» нажмите «Создать компанию». Заполните название, статус (trial), дату доступа, лимит пользователей. Введите имя и email администратора компании. Создайте.

4. **Вход как администратор компании (1 мин):** Выйдите, войдите под аккаунтом администратора компании. Вы попадёте в `/app` — дашборд.

5. **Проект и смета (1 мин):** Откройте «Проекты» → создайте проект. Откройте проект → создайте версию сметы → добавьте строки (материал, количество, цена) → утвердите смету.

6. **Заявка на материал (30 сек):** Откройте «Заявки на материалы» → создайте заявку → отправьте на согласование → согласуйте (как админ).

7. **Расход и отчёт (30 сек):** Добавьте расход по проекту. Создайте ежедневный отчёт. Вернитесь на дашборд — покажите бюджет vs факт.

8. **Команда (30 сек):** Откройте «Команда» → пригласите сотрудника. Покажите смену роли и блокировку.

9. **Блокировка (опционально):** Выйдите, войдите как SUPER_ADMIN → измените статус компании на «Приостановлена». Войдите под администратором компании — покажите экран блокировки с сохранением данных.
